# 01 · 需求与范围

## 1. 用户与场景

目标用户是短视频创作者、内容运营或剪辑新手。

他们通常只有一个模糊的 Brief，例如：

> 新手做短视频，字幕怎么加，30 秒，抖音。

真正需要的不只是一段文案，而是一份能继续制作的分镜脚本，并且每个产品事实都能回溯到来源。

## 2. 用户目标

1. 输入 Brief 后，得到可直接拍摄/剪辑的分镜脚本；
2. 脚本中的产品事实必须有来源，不能由模型编造；
3. 时长不满足时能自动修订，而不是直接交付；
4. 缺少平台或时长时，系统应暂停并追问；
5. 没有素材、工具失败或规则不满足时，系统应明确停止；
6. 能上传资料，构建自己的知识库，并观察检索过程。

## 3. 产品范围

### 本次实现

- 短视频脚本生成 HTTP API；
- LangGraph 自定义运行时；
- DeepSeek 动作选择与脚本生成；
- DashScope embedding 与 reranker；
- PostgreSQL + pgvector；
- BM25 + 向量 + RRF + rerank；
- Parent-Child 知识库入库；
- PDF / DOCX / TXT / MD / CSV / JSON 上传；
- Fact Ledger 与规则检查；
- 浏览器控制台；
- 五类验收状态。

### 非目标

- 扫描件 PDF 的 OCR；
- 多租户、权限与账号体系；
- Redis/Celery 或跨进程任务队列；
- 对象存储与多实例部署；
- 视频渲染、剪辑工程导出；
- 真实投放数据回流与自动优化。

## 4. 功能需求

### 4.1 Brief 输入

必填：

- `topic`
- `platform`
- `target_duration_sec`

可选：

- `audience`
- `style`

缺必填字段时，状态必须是 `WAITING_INPUT`，不能猜测。

### 4.2 脚本生成

输出至少包含：

- 标题；
- 多个分镜；
- 每个分镜的画面、口播、字幕、时长；
- 每个分镜引用的 claim；
- 使用的来源列表；
- 估算总时长；
- 规则检查结果与风险。

### 4.3 事实与规则

- 口播必须包含所引用 claim 的原文；
- claim 的 `source_id` 必须存在于素材白名单；
- 没有效果数据时，不得输出百分比、提升、增长类结论；
- 禁用“最”“第一”“绝对”等绝对化表述；
- block 级违规不能返回 `SUCCESS`。

### 4.4 知识库

- 支持上传 PDF/DOCX/TXT/MD/CSV/JSON；
- 解析后切分为 Parent/Child；
- Child 做 embedding 并进入混合检索；
- Parent 作为 Writer 上下文返回；
- 文件解析/切片/embedding 全部成功后自动 active；
- 支持文档列表、切片预览、下架、永久删除；
- reranker 失败时显式降级并记录风险；
- 提供固定 golden set 的检索评估。

### 4.5 预算与未完成

- 设置最大步数和最大工具调用次数；
- 达到上限时返回明确的 `MAX_STEPS`，不能继续无限循环；
- 结果中保留已执行的步数和工具次数；
- 示例见 `examples/scenarios/f_max_steps.json`。

### 4.6 可观测性

- 每次运行有 `run_id`；
- 事件流支持 SSE；
- Trace 包含动作、参数摘要、观察和决策依据；
- 不记录模型隐藏推理和密钥；
- 失败必须有状态、原因和建议。

## 5. 成功标准

### 功能验收

| 场景 | 期望 |
|---|---|
| 正常 30 秒 | `SUCCESS`，引用 P01/上传素材，时长在容差内 |
| 缺平台或时长 | `WAITING_INPUT`，missing_fields 准确 |
| 连续空检索 | `NO_MATERIAL`，不生成脚本 |
| 检索工具失败 | `TOOL_ERROR`，不伪造结果 |
| 目标 15 秒仍超时 | `UNSATISFIABLE_DURATION`，返回卡点与建议 |

### 工程验收

- `pytest` 全绿；
- 真实 PostgreSQL + pgvector 可完成迁移和入库；
- 六种文件格式能上传并进入检索；
- 真实模型路径至少成功完成一次生成；
- README 中的运行命令可复制执行；
- 不提交真实密钥和用户隐私。

## 6. 关键取舍

1. **先保证可解释，再追求模型自由度**：流程由 LangGraph 控制，不交给 `AgentExecutor`。
2. **先做合成知识库，再考虑 OCR**：当前数据用于验证流程，不冒充真实产品文档。
3. **先做单实例，再考虑队列**：演示范围内用进程内任务，生产化再升级。
4. **rerank 不假设一定有效**：评估面板会如实展示增益或损失。
